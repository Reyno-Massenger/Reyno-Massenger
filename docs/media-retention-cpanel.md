# 72-hour chat-media retention (cPanel)

The maintenance job keeps message rows, captions, reactions, and other chat history in the database. It removes only the server-side file blob for an old sent chat image, video/video-note, voice/audio attachment, document, or GIF. Unsent scheduled messages are not expired. The message remains in the conversation and the client receives an explicit “media expired” state. A copy already cached on a particular device may continue to work, but caching is not guaranteed across devices, reinstalls, or cache eviction.

Profile photos (including legacy URL-only references), story media, sticker messages/assets, and saved GIF assets are excluded from this retention policy. If a GIF is also present in the saved-GIF library, its media file is protected. The job writes one rolling ZIP containing the database and chat metadata only; uploaded media bytes are intentionally excluded so the archive does not defeat the storage-saving goal. Consequently, the ZIP can restore text/history and metadata, but cannot restore expired attachments.

## Configure

1. In cPanel File Manager, create a private writable directory for backups and the cron log outside `public_html` (for example `/home/CPANEL_USER/private`). Set `BACKUP_DIR` in `backend/.env` to an **absolute directory outside `public_html` and outside `UPLOAD_FOLDER`**, for example `/home/CPANEL_USER/private/reynooo-backups`. Do not serve or symlink this directory from the web root. The job applies restrictive directory/file permissions where the host permits it.
2. Ensure the cPanel Python virtual environment has the backend requirements installed. For a MySQL database, `mysqldump` must be available on `PATH`; SQLite databases are backed up directly. Video crop processing also requires `ffmpeg` with `libx264` and AAC encoders available to the web application; without it, crop uploads fail safely rather than silently sending an uncropped file.
3. Add an hourly cPanel cron entry (the script checks its own 72-hour timers):

   ```cron
   0 * * * * /home/CPANEL_USER/virtualenv/reynooo/backend/3.11/bin/python /home/CPANEL_USER/reynooo/backend/scripts/retention_maintenance.py >> /home/CPANEL_USER/private/reynooo-maintenance.log 2>&1
   ```

   Replace the paths and Python version with the values shown by cPanel. The script loads the backend `.env` from its own directory. Hourly checks keep expiry within roughly one hour of the 72-hour cutoff; backup replacement occurs once 72 hours have elapsed since the prior successful ZIP.

The archive is written to a temporary file, verified, and atomically replaces `reynooo-chat-metadata-latest.zip`; a failed backup does not replace the existing archive. If a due backup fails, media deletion is skipped. The archive contains sensitive database/chat data: keep the private directory inaccessible to the web server and restrict account access.

## Operational notes

- A full media ZIP would retain the storage cost of the media and temporarily need extra space while being built; this configured policy deliberately does not include media.
- The `Reached max children process limit` message is generated by the hosting server’s LiteSpeed/LSAPI process cap, not Flask. Ask the hosting provider whether they can raise the account limit; application code cannot safely override the server-wide limit.
- FCM OAuth rejection is separate from media retention. Rotate any rejected Firebase service-account key in Google Cloud, install the replacement as a private cPanel secret, and restart the Python application. Do not put the replacement key in the Git checkout.
